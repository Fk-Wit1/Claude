Phase 00 · Design

Two sessions, never both

The whole plan rests on one decision: the TV session and the streaming session are mutually exclusive. Sunshine stops one and starts the other when a client connects, and reverses it on disconnect.

This isn't a compromise — it dodges a hard blocker. Steam permits one running instance per user account, so two concurrent sessions would need a second Linux user with its own Steam install and library. You are one person; you're either on the sofa or on the Deck. Making the sessions exclusive makes that constraint free.

Why not just capture Gaming Mode

You could point Sunshine at the existing gamescope session with KMS capture — far simpler. But the stream then inherits the TV's 4K mode, so VCN 2.0 encodes 4K just to downscale onto a 1280×800 panel. That's the option you rejected, and it's kept here only as the fallback in Thin ice.

Phase 01 · Before the installer

BIOS and hardware

Settle these first — several are painful to change once the box lives behind the TV.

  • Memory: enable A-XMP to 3600 MT/s, then confirm FCLK sits at 1800 MHz for a 1:1 ratio. This is the Zen 3 sweet spot — don't push past it.
  • Above 4G Decoding and Resizable BAR on. Gains on RDNA 1 are modest and title-dependent, but it costs nothing to try.
  • ErP / Energy Saving: OFF. ErP cuts standby power to the NIC and silently kills Wake-on-LAN. This is the single most common reason a headless box won't wake.
  • Wake on PCI-E / LAN: enabled.
  • Wired Ethernet to the host, non-negotiable. WoL over Wi-Fi is unreliable, and streaming wants the stable link. Wi-Fi is for the clients.
Worth doing now

16 GB is the weakest spec in the build. Running a compositor, Steam, a game and Sunshine's encode path together will make you feel it. 32 GB is the cheapest meaningful upgrade left on AM4 — and far easier to fit on a bench than behind a TV unit.

Phase 02 · Base OS

Install Bazzite

Grab the bazzite-deck image for AMD from bazzite.gg — the Handheld/HTPC edition. It boots straight into Steam Gaming Mode and keeps Desktop Mode behind the power menu, which is exactly the console behaviour you want. Non-Steam-Deck hardware is supported on this image provided the GPU is a modern AMD part; yours qualifies.

Storage: use the 2 TB, ignore the 128 GB

Install to the SN770 as a single whole-disk btrfs root. Don't split root and games across the two drives.

Bazzite keeps two full deployments plus Flatpaks in /var, and image sizes have grown; 128 GB is uncomfortably tight for that on its own, and splitting means babysitting two Steam libraries forever. One big filesystem on the faster drive is simpler and faster. Leave the 128 GB unmounted as a spare — it's a fine place for a second library or a rescue install later.

On first boot: sign into Steam, let it update, confirm Gaming Mode comes up on the TV. Get this working before you touch anything below.

Phase 03 · Display
Couch

Pin the TV's EDID

The 5600X has no integrated graphics, so the 5700 XT is the only display path. When the TV or AVR powers off, the HDMI connector drops and the session can collapse or renegotiate to a junk mode. Pinning a fake EDID makes the output exist unconditionally.

Find the connector

for p in /sys/class/drm/*/status; do
  con=${p%/status}; echo -n "${con#*/card?-}: "; cat "$p"
done

Note the name that reports connected with the TV on — likely HDMI-A-1, but verify rather than assume.

Capture and stage the EDID

# with the TV on and awake
sudo mkdir -p /usr/local/lib/firmware/edid
sudo cp /sys/class/drm/card*-HDMI-A-1/edid \
        /usr/local/lib/firmware/edid/tv.bin
Atomic detail

/usr/lib/firmware is read-only on Bazzite, which is why the file goes to /usr/local/lib/firmware and why firmware_class.path below is required — without it the kernel never looks there.

Set the kernel arguments

sudo rpm-ostree kargs \
  --append-if-missing="firmware_class.path=/usr/local/lib/firmware" \
  --append-if-missing="drm.edid_firmware=HDMI-A-1:edid/tv.bin" \
  --append-if-missing="video=HDMI-A-1:e"

Both display arguments are load-bearing: drm.edid_firmware alone doesn't take, and video=…:e alone gives you a connector with no modes. Reboot, then test it properly — power the TV off at the wall and confirm the connector still reports its modes. If it doesn't, a £5 HDMI dummy plug does the same job in hardware.

Phase 04 · The interesting part
Stream

The headless session

A second compositor, running on nothing, at whatever resolution the client asks for.

Get this order right

Gamescope launched embedded from a TTY and captured by Sunshine produces RTSP timeouts — a known, reported failure. Gamescope nested inside another compositor works. So the stack is Sway-headless on the bottom, gamescope nested inside it, Steam inside that. Don't collapse those layers.

Layer Sway

rpm-ostree install sway
systemctl reboot

This is a real cost on an atomic image — every future update rebuilds with the layered package, so updates get slower. It's the price of the separate-session design.

The compositor unit

~/.config/systemd/user/sway-sunshine.service:

[Unit]
Description=Headless Sway for Sunshine
After=graphical-session-pre.target

[Service]
Type=simple
Environment=WLR_BACKENDS=headless,libinput
Environment=WLR_RENDERER=vulkan
Environment=LIBSEAT_BACKEND=noop
Environment=WAYLAND_DISPLAY=wayland-1
Environment=XDG_SESSION_TYPE=wayland
ExecStartPre=-/usr/bin/rm -f %t/sway-ipc.sock
ExecStart=/usr/bin/sway -c %h/.config/sway/sunshine.conf
Restart=on-failure

[Install]
WantedBy=default.target

Your account needs to be in the input group for LIBSEAT_BACKEND=noop to reach input devices. The reference implementation for this pattern uses gles2, but that's an NVIDIA-specific workaround for DRM format modifier issues — on AMD, Vulkan is the right choice. Fall back to gles2 only if you hit renderer errors.

What runs inside it

In sunshine.conf, disable every physical input device so keyboard and mouse don't leak into the streaming session, then launch the nested stack:

exec gamescope -W 1280 -H 800 -f -- steam -gamepadui

-W/-H is gamescope's output size; -w/-h sets the game's internal render size if you want to render below the output and let FSR upscale.

Follow the client's resolution

Sunshine exports SUNSHINE_CLIENT_WIDTH, SUNSHINE_CLIENT_HEIGHT and SUNSHINE_CLIENT_FPS to its prep commands. A two-line script resizes the headless output to match whichever client just connected:

#!/usr/bin/bash
swaymsg output HEADLESS-1 mode \
  "${SUNSHINE_CLIENT_WIDTH}x${SUNSHINE_CLIENT_HEIGHT}@${SUNSHINE_CLIENT_FPS}Hz"

This is what buys you the Deck's native 1280×800 and the Surface's 3:2 from the same host without either compromising the other.

Audio isolation

Create a persistent PipeWire null sink named sink-sunshine-stereo and point the streaming session at it. Keep it alive independent of connection state, and add a prep command that restores the host's default sink — Sunshine will otherwise hijack it and you'll lose TV audio in a way that's baffling to debug later.

Phase 05 · Host
Stream

Sunshine

Sunshine ships with Bazzite; you only enable it:

ujust setup-sunshine

Bazzite offers Flatpak and Homebrew builds. Take Homebrew — it's the one Bazzite recommends when you're outside a normal desktop session, and the Flatpak needs flatpak-spawn --host in front of every prep command, which gets ugly fast.

Then open https://localhost:47990, set a username and password, and configure:

SettingValueWhy
EncoderVAAPIThe AMD path on Linux
Adapter/dev/dri/renderD128Verify the node number
CodecHEVCSee below — not optional
AV1OffVCN 2.0 has no AV1 encoder
Bitrate~30 MbpsWired host, 1280×800
Audio sinksink-sunshine-stereoKeeps game audio off the TV
Force HEVC

Navi 10 is VCN 2.0 — H.264 and HEVC only; AV1 encode arrives with RX 7000. And AMD's H.264 encoder on this generation is genuinely poor: the consistent report is blocky output that needs endless tuning, where HEVC on the same card looks clean immediately. Both your clients decode HEVC. Set it and don't leave it on auto.

The session switch

This is where the architecture becomes real. In Sunshine's Do/Undo commands:

# Do — on client connect
systemctl --user stop gamescope-session.service
systemctl --user start sway-sunshine.service

# Undo — on disconnect
systemctl --user stop sway-sunshine.service
systemctl --user start gamescope-session.service

Check the exact unit name for Gaming Mode on your install before wiring this up. Test the Undo path deliberately — a half-failed teardown that leaves you with neither session running is the failure mode that requires a keyboard behind the sofa.

Phase 06 · Clients
Stream

Deck and Surface

Steam Deck

  • Moonlight from Flathub. Stream at 1280×800 to match the panel exactly — no scaling on either end.
  • 60 Hz on LCD; 90 Hz on OLED if the link holds it. HEVC, ~30 Mbps.
  • Add Moonlight to Steam as a non-Steam game so it launches from Gaming Mode without ever visiting the desktop.

Surface

  • 3:2 display, so pick a 3:2 stream resolution — 1920×1280 is the sensible target. The headless output will follow it via the resize script.
  • Its Intel iGPU decodes HEVC in hardware; confirm hardware decoding is actually on rather than silently falling back to software.
Phase 07 · The other job
Couch

HTPC duties

  • Kodi or Jellyfin as a Flatpak, added to Steam as a non-Steam shortcut so it's reachable from Big Picture with a controller.
  • HDR works through gamescope on AMD. Over HDMI 2.0b you're at 4K60 10-bit 4:2:0 — fine for film, and the bandwidth ceiling is why.
  • Audio passthrough to an AVR via PipeWire if you have one; set the HDMI sink's profile before assuming bitstreaming works.
No CEC on this card

The 5700 XT has no HDMI-CEC, so your TV remote will not drive Kodi and the box won't follow the TV's power state. If remote control matters, budget for a Pulse-Eight USB-CEC adapter. Otherwise plan on a controller or a small wireless keyboard as the only input.

Phase 08 · Power
Both

Wake and power

Persist Wake-on-LAN through NetworkManager rather than a one-shot ethtool call, which won't survive a reboot:

nmcli connection modify "Wired connection 1" \
  802-3-ethernet.wake-on-lan magic

Then add the host's MAC to Moonlight on the Deck so it can wake the box before connecting. Verify by suspending, waking from the Deck, and streaming — all without touching the tower. That round trip is the real acceptance test for "headless".

If suspend proves flaky on this platform, leaving the machine at idle is a legitimate answer for a box that's also a media player.

Honesty

Where this plan is on thin ice

Phases 01–03 and 05–08 are well-trodden. Phase 04 is not, and you should know exactly where the uncertainty sits before you spend an evening on it.

  • The reference implementation is NVIDIA-targeted. The headless-Sway + Sunshine pattern is proven, but the published version assumes NVENC and contains no AMD guidance. The architecture translates directly and VAAPI is well-supported — but you will be on less-documented ground, and the renderer and capture path are where I'd expect friction.
  • Verify the nested/embedded distinction yourself. It comes from a Sunshine bug report, not from AMD-specific testing on Bazzite.
  • Layering Sway costs you atomic-update speed permanently. If that annoys you more than resolution mismatch does, the trade is worth revisiting.
The fallback, if Phase 04 fights you

Enable Sunshine with KMS capture against the existing Gaming Mode session and accept that the stream inherits the TV's resolution. You lose Deck-native rendering and waste encoder budget, but it's a well-supported path on Bazzite and it works. Bank Phases 01–03 first either way — they're useful under both designs.
